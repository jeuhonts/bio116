BLAST on the command line

The companion tutorial ran BLAST on NCBI's website. Here you run the same programs on your own computer with NCBI's BLAST+ package. You install it, build your own databases, run protein and nucleotide searches, and turn the results into tables a script can read. Every command on this page was run exactly as shown, and every output is real.

  • About 60 minutes
  • Needs: a terminal (macOS, Linux, or Windows with WSL); about 10 MB of files
  • Follows: BLAST at NCBI
  1. 1Build a databaseTurn the E. coli proteome into a BLAST database.
  2. 2First searchDoes E. coli have a hemoglobin? Six human and plant globins go looking.
  3. 3OptionsSee how one real hit responds to database size, matrix and task.
  4. 4NucleotidesMap β-globin mRNA onto the human β-globin gene cluster.

Why the command line?

Both routes run the same algorithm. They suit different jobs.

Best forA few queries, exploring results by eyeHundreds or millions of queries, pipelines
DatabasesNCBI's collections onlyAny FASTA file you have, plus NCBI's downloadable databases
Unpublished dataYour sequence is sent to NCBIStays on your machine
OutputInteractive page, downloadsText, tables, JSON or XML, ready for scripts
ReproducibilityDatabases change dailyYou control the program version and the database

Install BLAST+

Pick one route. Conda works the same way on macOS, Linux and WSL, so use it if you are unsure.

Conda (any system)
$ conda create -n blast -c conda-forge -c bioconda blast
$ conda activate blast
macOS with Homebrew
$ brew install blast
Ubuntu, Debian, WSL
$ sudo apt install ncbi-blast+
NCBI installers
# .dmg, .exe and .tar.gz files from
https://ftp.ncbi.nlm.nih.gov/blast/executables/blast+/LATEST/

Then check that it works:

$ blastp -version
blastp: 2.12.0+
 Package: blast 2.12.0, build Apr  1 2024 07:01:27

The outputs on this page come from BLAST+ 2.12.0, the version Ubuntu 24.04's package manager installs. NCBI's current release is 2.17.0 (July 2025), which is what conda and the NCBI installers give you. The commands are the same. Your numbers should match ours, apart from small differences in speed-related tasks such as blastp-fast. Two Ubuntu/Debian quirks: the database download script is installed as update_blastdb instead of update_blastdb.pl, and rpsblast as rpsblast+.

Get the sequences

Make a working folder and download five files from NCBI with curl. These links use NCBI's E-utilities efetch service. If you run many downloads, add a one-second pause between them.

$ mkdir blast_lab && cd blast_lab
$ E=https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi
# E. coli K-12 MG1655: every protein, and the genome
$ curl -s "$E?db=nuccore&id=NC_000913.3&rettype=fasta_cds_aa" > ecoli_k12.faa
$ curl -s "$E?db=nuccore&id=NC_000913.3&rettype=fasta" > ecoli_k12.fna
# six globins: human α, β, myoglobin, cytoglobin, neuroglobin; soybean leghemoglobin

Tidy the headers

NCBI's protein-per-gene file has long headers like this:

>lcl|NC_000913.3_prot_NP_417047.1_2533 [gene=hmp] [locus_tag=b2552] [db_xref=UniProtKB/Swiss-Prot:P24232] [protein=nitric oxide dioxygenase] [protein_id=NP_417047.1] [location=2685835..2687025] [gbkey=CDS]

BLAST uses the first word of a header as the sequence ID and reports it in every result. Short, unique IDs make results much easier to read. This awk script keeps the E. coli locus tag (b0001, b0002, …), gene name and product. Save it as tidy.awk:

# turn NCBI "fasta_cds_aa" headers into  >locus_tag gene product
/^>/ { match($0, /locus_tag=[^]]*/); id = substr($0, RSTART+10, RLENGTH-10)
       match($0, /gene=[^]]*/);      g  = substr($0, RSTART+5,  RLENGTH-5)
       match($0, /protein=[^]]*/);   p  = substr($0, RSTART+8,  RLENGTH-8)
       if (n[id]++) id = id "_" n[id]          # a few genes encode two products
       print ">" id " " g " " p; next }
{ print }
$ awk -f tidy.awk ecoli_k12.faa > ecoli.faa
$ grep hmp ecoli.faa
>b2552 hmp nitric oxide dioxygenase

The if (n[id]++) line is needed. Nine locus tags appear twice in the file. One example is dnaX (b0470), which makes two proteins, τ and γ, through ribosomal frameshifting. makeblastdb -parse_seqids rejects duplicate IDs, so the second copy becomes b0470_2.

Exercise 2: first search

  
E. coli has a globin: the flavohemoglobin Hmp (b2552), a nitric oxide dioxygenase with an N-terminal globin domain. Will human β-globin find it? First pull β-globin out of globins.faa, then search.

  

  
$ awk '/^>/{p = /HBB_HUMAN/} p' globins.faa > hbb.faa
$ blastp -query hbb.faa -db ecoli -out hbb_vs_ecoli.txt
$ less hbb_vs_ecoli.txt

About the warning: -max_target_seqs is not simply "print the top N". BLAST applies the limit during the search, so a small value can change which hits you get, not only how many. Shah et al. (2019) showed that this misunderstood option had affected published analyses. Use a generous value, or at least 5, and filter afterwards.

Tabular output

  
For anything beyond reading by eye, use a table. -outfmt 6 writes one line per alignment (HSP), with tab-separated columns. -outfmt 7 is the same table plus # comment lines that name the columns and count the hits.

  

  

  

  
The twelve default columns are qaccver saccver pident length mismatch gapopen qstart qend sstart send evalue bitscore (keyword std). You can choose your own by listing them in quotes after the 6 or 7. For example, qcovhsp (query coverage) and stitle (the subject's description) are often useful:

  

  

  

    
Build your own -outfmt real all-against-all output from the six globins

Exercise 3: options that change results

  
The neuroglobin–Hmp hit is a real but distant relationship, which makes it a sensitive test. Rerun the search with one option changed at a time:

The score of the alignment (41.6 bits) did not change with -dbsize, but its E-value rose 139-fold. Swiss-Prot has 186,063,409 residues and our E. coli database has 1,337,980, a ratio of 139. A hit that is convincing in a small, focused database can drop to borderline in a large one. So always report the database with the E-value.

Exercise 4: nucleotide searches

  
blastn: map an mRNA onto its gene cluster

  
Human β-globin mRNA (NM_000518.5, 628 nt) against the 81,706 bp β-globin cluster (NG_000007.3). For a one-off comparison you do not need a database: -subject takes a FASTA file directly. blastn has several -task modes, and the default megablast is tuned for near-identical matches.

  

  
$ for t in megablast dc-megablast blastn; do
    blastn -task $t -query hbb_mrna.fna -subject hbb_locus.fna -evalue 1e-5 \
      -outfmt "6 pident length qstart qend sstart send evalue bitscore" > locus_$t.tsv
  done

  

    
Where the mRNA aligns each bar is one HSP; gene positions from the NG_000007.3 record

    

    
    

  

  

  
    
    
  • Exons appear as separate hits. The mRNA has no introns, so each exon of the gene aligns on its own. Query positions 1–143, 141–365 and 365–628 are the three exons.
    • 
    
  • megablast (word size 28) finds HBB at 100% identity, its close paralog HBD (δ), and one exon of HBE1 (ε): 7 HSPs.
    • 
    
  • dc-megablast (discontiguous seeds, meant for cross-species comparisons) adds both γ genes (HBG1, HBG2), another ε exon and the pseudogene HBBP1: 15 HSPs.
    • 
    
  • blastn (word size 11) also finds the last ε exon: 16 HSPs. Smaller seeds find more distant matches, as with protein word size.
    • 
  

  
tblastn: find a gene in a genome

  
tblastn translates the database in all six reading frames. It finds protein-coding regions even when no one has annotated them. Build a nucleotide database from the E. coli genome and search with neuroglobin:

$ tblastn -query ngb.faa -db ecoli_genome -evalue 1e-3 \

Many queries and scripts

  
A tabular file is easy to process. Here, every globin is searched against every other, and a short Python script picks each protein's best non-self hit.

  

  
$ blastp -query globins.faa -db globins -evalue 10 -out allvall.tsv \
    -outfmt "6 qseqid sseqid pident length evalue bitscore"

  

    
All against all best E-value for each query (row) and subject (column); darker = more significant

    

    
Look for the gaps. β-globin and myoglobin never find each other, in either direction, even though they share a fold and heme-binding histidines. Leghemoglobin → myoglobin is missing too. Also compare mirror cells: α → leghemoglobin and leghemoglobin → α both give E = 0.002, but most pairs differ a little between directions. Composition-based statistics adjust the scores for each query, so a search is not exactly symmetric.

  

  

    

      
best_hits.py
import csv
cols = "qseqid sseqid pident length evalue bitscore".split()
best = {}
with open("allvall.tsv") as fh:
    for row in csv.reader(fh, delimiter="\t"):
        hit = dict(zip(cols, row))
        if hit["qseqid"] == hit["sseqid"]:
            continue                                   # skip self-hits
        q = hit["qseqid"].split("|")[2]                # sp|P68871.2|HBB_HUMAN -> HBB_HUMAN
        if q not in best or float(hit["bitscore"]) > float(best[q]["bitscore"]):
            best[q] = hit
for q, h in best.items():
    print(f'{q:12s} -> {h["sseqid"].split("|")[2]:12s} {h["pident"]:>7s}% id  E = {h["evalue"]}')

    

    

      
$ python3 best_hits.py
HBA_HUMAN    -> HBB_HUMAN     43.448% id  E = 1.10e-37
HBB_HUMAN    -> HBA_HUMAN     43.448% id  E = 1.13e-37
MYG_HUMAN    -> CYGB_HUMAN    28.667% id  E = 4.31e-21
CYGB_HUMAN   -> MYG_HUMAN     29.412% id  E = 2.01e-22
NGB_HUMAN    -> CYGB_HUMAN    25.385% id  E = 2.30e-09
LGB3_SOYBN   -> CYGB_HUMAN    24.812% id  E = 3.85e-06

      
α and β pick each other, as expected. But myoglobin's best hit is cytoglobin, not a hemoglobin, because it never found β-globin at all. The best BLAST hit is not always the closest relative.

NCBI's databases, and -remote

  
You can download NCBI's prebuilt BLAST databases (swissprot, nr, core_nt, refseq_protein, and others) instead of building your own. They are updated regularly and include taxonomy information.

  

  
$ update_blastdb.pl --showall                 # list what is available
$ update_blastdb.pl --decompress swissprot    # download and unpack Swiss-Prot
$ blastp -query hbb.faa -db swissprot -evalue 0.05 -max_target_seqs 100 -seg yes

  

  
The last command uses the settings NCBI's FAQ recommends for reproducing web blastp results. Check the database sizes first:

Swiss-Prot fits on any laptop. nr does not: it needs about three-quarters of a terabyte of disk, and a fast search keeps over 400 GB in memory, which means a server or computing cluster. For a single protein against nr, use the website or -remote. For local work, choose a smaller database such as swissprot, refseq_select_prot or one organism's proteome, as in Exercise 1. nt versus core_nt shows why NCBI made core_nt the default: about the same number of sequences, but under a quarter of the bases, because most of nt's bulk is large genome sequences.

  
Any BLAST+ search program can also send the search to NCBI's servers instead of running locally, by adding -remote and naming an NCBI database:

  

  
$ blastp -query hbb.faa -db swissprot -remote -outfmt 6

  

  
We could not run these three commands in our build environment, which blocks NCBI's download server and the BLAST+ remote service, so no output is shown. A -remote search waits in NCBI's queue like a web search and is meant for occasional use. Scripted searches of nt are sent to core_nt, as the web tutorial explains. For large jobs, download the database to a machine with enough disk and memory and search there.

Check yourself

  
1. You run blastp -query q.faa -db proteins.faa and get "No alias or index file found". Why?
    
-db needs a BLAST database, not a FASTA file. Run makeblastdb -in proteins.faa -dbtype prot -out proteins first and pass -db proteins. For a quick one-off comparison, -subject proteins.faa also works without a database.

  
2. The same command gives more hits on your laptop than a classmate gets on the NCBI website. Is one of you wrong?
    
Probably not. The defaults differ: the command line reports up to 500 hits with E ≤ 10, the web up to 100 with E ≤ 0.05, and word sizes differ too. The databases may also differ. Set the options explicitly on both.

  
3. Human β-globin found nothing in E. coli, but neuroglobin found Hmp. Does E. coli lack a β-globin homolog?
    
No. Hmp's globin domain is homologous to all animal globins, β-globin included. Neuroglobin just kept enough similarity for blastp to detect it. A missing BLAST hit is not evidence of absence. A profile method (PSI-BLAST, HMMER) or a structure comparison can find what pairwise BLAST misses.

  
4. A hit has E = 6 × 10⁻⁶ in your E. coli database. A reviewer asks for its significance against Swiss-Prot. Do you need to rerun the search?
    
To see which other hits appear, yes. For this hit alone, -dbsize or the ratio of database sizes gives a good estimate. Swiss-Prot is 139 times larger, so E ≈ 9 × 10⁻⁴, still significant but far less striking.

  
5. In -outfmt 6 output from blastn, a row has sstart 4,500 and send 3,900. What does that mean?
    
The query matches the minus (reverse-complement) strand of the subject, between positions 3,900 and 4,500.

  
6. Why did the β-globin mRNA produce three separate alignments to the HBB gene instead of one?
    
The gene has two introns. The mRNA matches the three exons, and BLAST reports each as its own HSP because the intron sequence in between is absent from the query. Gap penalties would make a single alignment across a 100 to 900 nt intron score worse than three separate ones.

  
7. Why keep -max_target_seqs at 5 or more, even if you only want the best hit?
    
The limit is applied during the search, not after. With very small values, the hits BLAST keeps are not guaranteed to be the best ones overall. Ask for more and take the top one yourself.
